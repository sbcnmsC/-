# Lexicon Brawl · 像素背词赛车

像素风雅思单词游戏：奖励成长 + 艾宾浩斯复习 + 错题集 + 自动发音 + 多人赛车追逐对战。纯静态页面，无需构建，打开 `index.html` 即可使用。

## 功能

**学习**
- 奖励反馈：XP、连击加成、升级、每日目标、连续打卡、成就徽章
- 艾宾浩斯复习：5 分钟 → 30 分钟 → 12 小时 → 1 天 → 2 天 → 4 天 → 7 天 → 15 天，答错回到起点
- 词库：「痛单词 TOP 10000」共 9999 词（见下方“词库说明”）。新词默认按词表顺序出，可限定范围（前 500 / 1000 / 3000 / 全部）或改为随机；这些设置收在“学习设置”折叠区
- 自定义刷题数量：每轮 5 / 10 / 20 / 50 或自定义 1–200 题；先出到期复习和新词，不够时用已学词加练（加练答对不改变复习计划）
- 干扰项自动排除语义相近的选项（如 impact / influence 都含“影响”），洗牌使用 Fisher–Yates；做完一轮可点“再来一轮”
- 错题集：自动收录（含对战中答错的词），同一词连续答对 3 次后移出，可单独练习
- 例句与发音：切词自动发音，可设为 单词 / 例句 / 两者 / 关闭；答对答错有 8-bit 音效，可关闭
- 手机优化：大点击区域、安全区适配、震动反馈

**赛车追逐（2–8 人，房主选竞速或组队）**
- 每人一辆像素赛车，1000 米赛道，**车一直在跑**（基础时速 36 km/h），答题决定快慢：
  - 答对加速：基础 +7，连击最多 +5，答得越快越多；加速会随时间衰减，要持续答对才能保持高速
  - 答错或超时（每个单词 10 秒，切词重置）：加速被削掉、车辆打滑减速
- 追逐机制：紧跟在前车 35 米内获得**尾流加速**，落后领先者超过 120 米有**追赶加速**，落后时掉道具概率更高
- 13 种道具（连击 3 次必掉，最多持有 3 个，点击对手赛道可锁定目标，默认打最近的前车，自己第一时打最近的追兵）
  - 干扰对手背词：迷雾、黑屏、熄火（停车且 3 秒无法作答）、镜像（单词倒写）、乱码（元音变 *）、限时（只剩 4 秒）
  - 干扰对手赛车：油渍（减速 3.5 秒）、炸弹（击退 40 米并清空加速）
  - 己方：氮气、涡轮（接下来 3 次答对加速翻倍）、近道（前进 40 米）、护盾（8 秒免疫道具）、净化
- 房主可在大厅选择词库范围（前 500 / 1000 / 3000 / 全部），全员用同一范围出题
- 竞速：先冲线者为冠军，首名冲线后其余人有 15 秒冲线，结算显示名次、用时、答对数与最高连击
- 组队：红蓝两队，按全员名次积分（越低越好）判胜负，积分相同则看最佳名次
- 开赛 3-2-1 同步倒计时；每人本地模拟自己的赛车并广播位置与速度，其他设备按速度外推显示，不依赖设备时钟

## 目录

```
index.html        页面结构
style.css         样式（主题变量、像素组件、手机适配）
words.js          词库，格式 ["单词","词性","释义","例句"]
net.js            联机传输层（PeerJS 星型转发，供 GitHub Pages / 本地使用）
app.js            学习 / 计划逻辑（艾宾浩斯、错题集、发音、音效）
battle.js         赛车追逐对战（物理、道具、联机大厅）
main.js           初始化（最后加载）
tools/pdf_extract.py  从词表 PDF 提取单词（缺字用 OCR 补回）
tools/build_words.py  把提取结果整理成 words.js
tools/bundle.py   合并为单个 HTML：python3 tools/bundle.py → dist/lexicon-brawl.html
dist/             合并后的单文件版本（可直接用于 Claude 页面发布）
tests/            自动化测试（jsdom，模拟多人对战、联机、学习逻辑）
```

## 部署到 GitHub Pages

1. 推送到仓库后打开 **Settings → Pages**
2. Source 选 `Deploy from a branch`，分支 `main`，目录 `/ (root)`
3. 访问 `https://<你的用户名>.github.io/<仓库名>/`

## 本地运行

```bash
python3 -m http.server 8000   # 然后打开 http://localhost:8000
```

学习进度保存在浏览器 `localStorage`，换设备或清除数据会丢失。

## 关于联机

- **Claude 发布页**：使用内置 `room` 能力同步（presence 里放伤害计数、护盾和道具事件）。
- **GitHub Pages / 本地**：自动改用 `net.js` 的 PeerJS（WebRTC）星型转发。先输入房间号的人成为房主，其他人连接房主；**房主离开则房间关闭**。依赖 jsDelivr 加载 PeerJS 以及 PeerJS 公共信令服务器，网络受限（如部分国内网络）时可能连不上。想更稳可以自建 [PeerServer](https://github.com/peers/peerjs-server)，在 `net.js` 里给 `new Peer()` 传入 `host/port` 即可。
- 战斗逻辑只依赖 `peers()` / `presence(patch)` / `onPeers(fn)` 三个接口，可替换为其他实时后端。

## 词库说明

- 来源：你提供的「痛单词 TOP 10000」PDF（334 页，10000 行），导入 **9999 词**（有 1 个重复）。
- **PDF 的限制**：中文释义的文本层缺字（如“负面的”提取成“负 的”），长释义被截断成“...”。我的处理：
  - 按字符间距算出缺几个字，再用整页 OCR 的上下文补回（tesseract + chi_sim）；行尾缺字（如“豌豆”只剩“豌”）用 OCR 延伸；PDF 页面外还藏着一排未映射字符，用来校验，约 95% 吻合
  - 补不全的片段整段丢弃，被截断的最后一项丢弃；每个词保留前 3 个释义
  - 文本层完全没有释义的约 125 个词改用整行 OCR，**已逐个人工校对**；另有约 40 个被截断的单字释义和 5 个缺失词条也做了手工修正，记录在 `tools/manual_fixes.json`
  - 其余约 9800 个词条没有逐个核对，**仍可能有零星错字**，发现后直接改 `words.js` 对应一行
- 只有前 48 个高频词有手写的释义和例句；其余词答题后显示“单词 · 词性 · 释义”，不显示例句
- 想修正某个词，直接改 `words.js` 里对应一行即可；重新生成见 `tools/pdf_extract.py` 顶部说明
- 头像与道具图标是代码绘制的 8×8 像素图，无外部图片
- 字体用 Google Fonts（DotGothic16 / Press Start 2P），页面加载完成后异步加载，离线或加载慢时回退到系统字体
